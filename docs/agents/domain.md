# Domain docs

This repository uses a single-context layout:

- Domain vocabulary and boundaries: `CONTEXT.md`
- Architecture decisions: `docs/adr/`

Before exploring or changing code, read the relevant files when they exist. Missing files are expected and should not block work; domain-modeling workflows create them when decisions are established.

Use the vocabulary defined in `CONTEXT.md`. Surface any proposal that contradicts an existing ADR instead of silently overriding it.
